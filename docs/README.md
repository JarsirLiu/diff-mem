# Diff-Mem 工程方案设计文档

> 面向通用智能体的符号化状态记忆框架 —— 工程落地方案

---

## 核心设计原则

1. **AI 决定内容，引擎保证安全** —— AI 有创造性（命名、摘要），引擎有约束性（规范化、校验）
2. **软索引可漂，硬数据不漂** —— summary/tags 容许漂移，Body 事件不可逆追加
3. **模型永不面对全量** —— 检索始终分步导航，单步返回可控数量
4. **每一次写入都有据可查** —— 所有操作带 reason，完整操作日志可回溯

## 关键设计决策记录

### 决策 1：Path 由 AI 命名，引擎规范化

- **选择**：AI 提交命名意图，引擎做 6 步规范化（小写、去特殊字符、去重等）
- **拒绝的方案**：完全由引擎自动生成 path（AI 失去对分类的控制权）
- **理由**：分类结构是语义性的，只有 AI 能理解上下文做合理归类

### 决策 2：Summary 由 AI 决定，引擎做新旧对比

- **选择**：`diff_mem_update_summary` 要求提交 old_summary + new_summary，引擎抽取实体对比；有实体消失时要求 AI 在 reason 中解释，不做硬阻塞
- **拒绝的方案**：引擎自动从 Body 生成 summary（需要 LLM，成本高）；硬性要求保留全部旧实体（阻碍正常变更）；完全不校验（漂移不可控）
- **理由**：实体消失是正常的（人走了、方案换了），引擎防的不是"消失"本身，而是"AI 不知道自己丢了什么"

### 决策 3：检索 = list 导航 + search 索引

- **选择**：双轨制——list 逐层浏览，search 按标签/关键词定位
- **拒绝的方案**：全量 Header 加载后 LLM 筛选（不可扩展）；纯向量搜索（丢失结构信息）
- **理由**：树结构本身就是语义索引，结合倒排索引实现高效检索

### 决策 4：Body 事件永不修改

- **选择**：APPEND 是唯一的写入方式，不存在 update/delete event
- **拒绝的方案**：允许编辑历史事件（引入权限和一致性问题）
- **理由**：不可篡改性简化了设计，审计天然具备

### 决策 5：节点只有 active / archived 两种状态

- **选择**：记忆节点只有活跃和归档两种状态，支持 restore 恢复
- **拒绝的方案**：proposed/implemented/rejected 等中间态——那是文档流转的门禁，记忆节点是事实记录，不需要流程门禁
- **理由**：记忆的价值在于"是否还被需要"，不在于"流程走完了没有"。归档时机由 AI 自主判断（信息是否被消费、是否还有引用、重新被需要的可能性）

### 决策 6：引用关系构成图，不是简单的查表

- **选择**：节点间的引用关系维护为有向异构图，引擎在此图上实现可达性分析、环检测、连通分量、图增强检索
- **拒绝的方案**：引用关系只存不查（建了边但从不使用，浪费了结构信息）
- **理由**：引用图的真正价值在两个地方——归档前的影响评估（可达性）和检索时的关联召回（图增强搜索）。前者防止误操作，后者直接提升记忆系统的智能度
