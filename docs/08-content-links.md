# 08. 内容链接：记忆条目间的关联与门禁

> 链接写在 Body 内容里，门禁保证链接永不悬空——AI 看一条记忆，就能看见其相关记忆

---

## 一、设计立场：链接是内容，不是元数据

记忆条目之间的关联不需要独立的关系表。Diff-Mem 采用类似文档间超链接的模型：

- **链接写在 Body 事件文本里**，语法为 `[[/path/to/node]]`
- **Header 保持纯净**：只有路径、状态、标签、摘要、字段，不存任何关系元数据
- **引擎只做一件事：门禁**——保证链接指向的东西存在

这与 deepseek-harness 的文档链接校验同源：文档里写相对链接，校验脚本保证链接可解析；读者看到链接即可放心点过去。Diff-Mem 中"读者"是 AI，"点过去"是 `diff_mem_show`。

```
读取 /Projects/Alpha/Backend 时：
  → show 响应附带 links: ["/Decisions/认证方案"]        ← 我链接了谁
  → show 响应附带 backlinks: ["/Projects/Alpha"]        ← 谁链接了我
  → AI 判断这些相关记忆是否值得一看，自行决定是否加载
```

---

## 二、写侧门禁（create / append）

引擎在写入前用正则扫描事件文本，抽出所有 `[[...]]` 引用并逐一校验：

| 情形 | 行为 |
|------|------|
| 目标路径已存在 | 放行 |
| 目标是节点自身或祖先路径 | 放行（祖先在 create 时自动创建） |
| 目标不存在 | 拒绝写入，`LINK_TARGET_NOT_FOUND` + did-you-mean（最多 3 个相似路径） |
| 不是以 `/` 开头的路径 | 拒绝写入，`LINK_TARGET_INVALID` |

关键性质：**校验失败零副作用**——不创建节点、不追加事件、不自动建父路径。AI 拿到错误后修正链接重试即可。

事件流不可变，所以链接关系随历史一起被审计：谁在什么时候链到什么，Body 里全有记录。

---

## 三、读侧发现

| 响应 | 字段 | 含义 |
|------|------|------|
| `diff_mem_show` | `links` | 本节点 Body 中全部 `[[...]]` 指向的节点 |
| `diff_mem_show` | `backlinks` | 其他**活跃**节点 Body 中链接到本节点的节点列表（倒排索引实时查询） |
| `diff_mem_show`（window） | `links` | 全节点内容链接汇总（无论窗口加载了哪些事件） |

发现的价值在检索链路上：`search` 命中一条记忆 → `show` 看到它的 links/backlinks → 顺藤摸瓜加载相关记忆。AI 永远掌握是否深入的决定权，引擎只负责把邻居摆在眼前。

---

## 四、生命周期门禁

链接悬空只可能由节点消失引起，引擎在两个入口拦截（引用方查询走倒排索引，O(1) 定位）：

```
delete(A)：
  → 查倒排索引：谁链接了 A？
  → 有引用方 → 拒绝（LINKED_BY_OTHERS），列出引用方路径
  → AI 需先更新这些节点的 Body（移除或改指向），再删除

archive(A)：
  → 同样查索引，有引用方 → 警告但不阻止
  → 警告附三选一处置指引（借鉴 deepseek-harness 归档规则）：
    1) 改指到新的承接节点
    2) 有意引用历史快照 → 保留链接（归档节点仍是有效链接目标）
    3) 无意义 → 更新引用方 Body 移除链接
  → 归档可恢复，警告足以提醒 AI 权衡

restore(A)：
  → 检查 A 的出站 [[链接]]，目标已删除或已归档 → 警告列出悬空目标
  → AI 恢复后可立即修复 Body（deepseek-harness 无 restore，此为自有增强）
```

为什么 delete 硬拒绝、archive 只警告：delete 不可逆，悬空链接无法补救；archive 可 restore，且归档期间引用方仍能看到 backlinks 提示。

## 五、与结构化边方案的对比

| 维度 | 内容链接（当前） | 结构化边（已移除） |
|------|----------------|------------------|
| 工具面 | 无额外工具 | 需要 link/unlink 两个工具 |
| 关系语义 | 隐含在文本中，人机皆可读 | 显式 type（depends_on 等） |
| 一致性 | 门禁强制，永不悬空 | 依赖调用方自觉维护 |
| 审计 | 事件流天然记录链接历史 | 边的变更需额外审计 |
| 图算法 | 不可用（需先解析全部 Body） | 直接支持 BFS / 环检测 / 连通分量 |

当前规模下内容链接是正确的取舍。如果未来记忆网络需要拓扑保证（如硬依赖的环检测），可以在倒排索引的基础上平滑升级（把索引从内存落到存储层即可），不影响现有数据格式。

---

## 六、实现要点

- 正则：`[[([^\[\]\n]+)\]\]]`，`internal/engine/links.go`
- 反向引用由引擎内存中的**倒排索引**（`linkIndex`）维护：双向映射（目标→引用方、引用方→目标），create/append 增量更新，delete 清理，引擎启动时从存储全量重建，引用方列表排序输出保证确定性
- did-you-mean：按目标路径最后一段在现有节点路径中做子串匹配，最多返回 3 个
